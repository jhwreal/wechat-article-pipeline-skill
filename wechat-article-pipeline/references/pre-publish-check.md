# 发布前隐藏检查记录

本规则用于 Agent 的发布工作流，统一覆盖微信草稿导入、头条/小红书草稿与立即或定时发布、三平台同步。它不改变发布授权，也不在正文、工作台、签名或原创篇号中显示计数。直接绕过 Skill 调用底层 API 脚本不会执行这项自动检查。

## 发布前

1. 先取得工作台最新已保存的 Markdown，运行：

   ```bash
   python3 <skill>/scripts/article_check_state.py status <workspace>/files/<slug>.md
   ```

2. 用户明确说“这次不检查，直接发”“跳过检查”等时，尊重本次跳过：仅对本次流程、同篇同版本生效，三平台共用；不递增计数、不伪造报告、不保存永久豁免。“上传”“直接发”“赶紧发”本身不是明确跳过检查。
3. 未明确跳过且 `current_check_count >= 1` 时，复用当前版本的有效检查并阅读报告；检查过不等于问题已解决，按下方结果处理规则继续。技术包校验、复制前检查、仅核实数字、图片检查、写作差异复盘均不能替代全文或完整语言检查。
4. 未明确跳过且 `needs_check: true` 时，直接按 [article-check.md](article-check.md) 完成默认五项检查、保存报告并登记。先简短告知“当前稿还没有有效检查，我先检查，完成后继续上传”，随即实际执行；不要询问是否开始检查，不要发完提示就结束回合或等待用户回答。检查后改过稿的版本也自动检查。用户明确限定检查范围时遵从范围，说明未查部分，不以默认规则扩大范围。
5. 状态丢失、损坏或无法读取不等于已检查，也不是原地停止的理由：读取最新正文，完成实际检查并交付报告。损坏记录先保留备份再修复，不能编造历史次数；暂时无法登记时，保留本次报告、正文哈希和登记失败原因。当前版本已有本次实际完成的检查证据时，可以按结果继续本次授权流程，不能声称计数已更新。
6. 检查本身不授权改稿；仅按已有授权修改。若改稿，通读修订终稿并生成对应报告再登记。定时发布在提交定时任务之前完成检查；正文再次变化或新一轮发布重新运行 `status`。人工粘贴且无本地稿的文章先保存明确的 Markdown 来源，不能凭历史报告文件名猜测已检查。

## 检查结果与继续上传

- **没有需处理的问题**：在对话里简要报告检查已完成，继续原已授权的草稿导入或发布；不再询问是否发布。同篇同版三平台复用结果，不重复启动检查。
- **只有可选润色或结构建议**：在对话里列出建议并继续上传，保留用户原文；不要把偏好差异、刻意口语、引用或未能独立验证的个人经历自动当成错误。
- **发现已确认的错别字、严重实质性错误，或影响核心结论的关键事实缺口**：立即在当前对话列出位置、原句、具体改法及必要依据，附报告链接，不能只写到本地文件。已有改稿授权就落实、复核并继续；没有授权且需要用户取舍时，明确说“检查已完成，尚未上传，待处理以下问题”，只询问具体修改或取舍，不能退回“要不要检查”。用户已明确要求保留的原话按其授权处理，不反复询问。
- **事实核查受限**：继续完成能做的检查，说明哪项未核实及是否影响核心判断；非关键局限不阻断上传，影响核心判断的缺口按上一条处理，不把缺证据说成已证实错误。
- **遇到真正阻断**（例如稿件无法取得、账号失效、平台要求人工处理）：当次就说明已完成什么、是否已上传、阻断原因和需要的具体动作。不能让用户以为仍在后台工作；平台原有授权、提交熔断和安全要求保持有效。

## 检查完成后

检查开始先运行 `status` 并保留其 `article_sha256`；实际完成阅读和报告后才登记：

```bash
python3 <skill>/scripts/article_check_state.py record <workspace>/files/<slug>.md \
  --expected-sha256 <检查开始时的article_sha256> \
  --report <workspace>/files/<slug>.check.md --scope full
```

- 默认五项检查用 `full`；覆盖全文错别字、语法、病句、标点的语言检查用 `language`；仅查错别字、事实、局部段落等用 `other`，保留记录但不满足发布前语言检查要求。不得擅自扩大用户指定的检查范围。
- 检查过程稿件变化会拒绝登记；不能仅对新稿计算哈希来冒充已经读过。检查并修改后应重新通读最终版本，保存该版本报告，然后登记。
- 隐藏状态保存在 `files/.article-checks/<slug>.md.json`，累计次数与当前正文 SHA-256 的有效次数分开。报告路径与哈希也需匹配；报告删除或被改写后旧记录不再放行。同一报告重复登记不会重复计数。
- 历史报告默认不补记。只有核实报告确实记录当前正文哈希、范围包括全文语言检查且实际完成，才可登记；不能仅因存在 `.check.md` 便增加计数。
- 此脚本只保存检查证据，不会自动识别语法或判断报告质量；必须由 Agent 实际执行检查。不要在文章包 JSON 或 HTML 添加可见开关，也不要修改 `.env` 或原创篇号。
