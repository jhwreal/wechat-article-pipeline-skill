# 小红书 Chrome + Computer Use 长文同步流程

仅在用户明确要求同步、保存草稿或发布小红书长文时使用本流程。复用用户 Chrome 中已有的登录态。Chrome 用于页面检查、权限设置、编辑器核验、排版和结果核验；Computer Use 专门用于在工作台选择“小红书格式”并点击 `复制为小红书格式`、完成 macOS 系统剪贴板和小红书正文粘贴。

## 官方能力边界

- 截至 2026-08-01，小红书公开的[分享开放平台](https://agora.xiaohongshu.com/doc)提供移动端分享 SDK，可把图片或视频素材带入小红书 App 的发布工具，但它不是面向创作者账号的服务器端发稿 API。
- 官方[分享 SDK 常见问题](https://agora.xiaohongshu.com/doc/qa)明确说明，标题和文案自动填充当前受限；因此它不能替代本流程的长文标题、正文、标题层级和图片排版同步。
- 小红书[小程序开放平台](https://miniapp.xiaohongshu.com/home)的“笔记发布能力及入口”是小程序在站内的入口能力，不等于创作者笔记或长文的直接创建 API。
- 不调用、复制或固化 `creator.xiaohongshu.com` 的私有接口、Cookie、localStorage、token 或页面内部请求。当前可维护路径是已登录 Chrome + 可见 UI + macOS 系统剪贴板。

## 权威内容

- 以用户确认的最终 Markdown/工作台正文为准，不从小红书自动保存的旧草稿反向覆盖本地稿。
- 标题使用用户指定的最终标题。正文不要重复插入文章总标题、公众号原创篇号或微信专属签名。
- 来源名称可以保留为纯文本，但正文不得包含外网超链接。
- 复制前记录最终标题、发布方式、预期图片数、Markdown `##` 数量、Markdown `###` 及更深标题数量，以及首段、至少两个正文哨兵句和末段。

## 工作台复制规则

工作台的“选择小红书格式 → 点击 `复制为小红书格式`”是已有文章进入小红书长文编辑器的唯一正文入口。该复制路径必须：

1. 移除文章总标题、公众号原创篇号和微信签名。
2. 移除外部链接，只保留链接文字。
3. 从 Markdown 语义 DOM 直接生成小红书版本，不得从已经被微信排版扁平化为段落的 HTML 二次转换。
4. 把 Markdown `##` 对应的正文标题映射为小红书 `h1`；把 Markdown `###` 及更深标题映射为小红书 `h2`。
5. 保留图片的原始位置和 `img` 结构，并在复制前把每张图片转为 `data:image/...;base64` 内嵌数据；不得使用 loopback、`file:` 图片或文字占位符。真实小红书编辑器的站内复制实测也会把图片写成这种内嵌数据。
6. 尽量保留段落、编号列表、项目列表和引用的语义结构。小红书长文可能把粘贴的 `strong` 降为普通文本，不把加粗作为同步硬门槛。
7. 清除微信专属的 class、id、`data-*` 和内联样式。

工作台顶部的平台下拉框默认是微信格式，也可切换到头条或小红书格式。选择小红书格式后，唯一复制按钮会变为 `复制为小红书格式`，并优先通过浏览器原生选区复制生成系统剪贴板中的 `text/html` 和 `text/plain` 表示。这条路径模拟富文本编辑器自身的复制行为，而不是把微信样式 HTML 重新拼成小红书正文。

必须用 Computer Use 点击一次 `复制为小红书格式`，让带有 H1/H2 和 Base64 内嵌图片的完整富文本进入 macOS 系统剪贴板；再切到小红书长文编辑器，聚焦 ProseMirror 正文区并执行一次 `super+v`。不得用浏览器虚拟剪贴板替代，不得把纯文本重建当成富文本同步成功。实测小红书内部“复制后再粘回”的 `text/html` 同样包含 H1/H2 与 `data:image`；粘贴后平台会把图片转为自己的 `xhscdn` 托管地址。工作台复现这一标准结构，粘贴后仍必须做只读 DOM 和图片托管核验。

## Chrome 路径

1. 使用 Chrome 控制 skill 和 Computer Use skill，复用当前 Chrome 登录态并给会话命名。
2. 打开干净的长文编辑器：`https://creator.xiaohongshu.com/publish/publish?from=homepage&target=article`。若当前页面已有未知内容，停止写入；不要覆盖或修补来源不明的旧草稿。
3. 填入最终标题。当前长文编辑器的可见上限为 64 字；超过上限时工作台必须显示警告，禁止进入排版或提交阶段。
4. 在真实工作台选择“小红书格式”，核对复制前检查、两级标题与图片位置，再用 Computer Use 完成“点击复制为小红书格式 → 切到小红书 → 聚焦 ProseMirror → macOS 系统粘贴”，一次性粘贴结构化正文。独立测试页、小样 HTML 或手工拼出的富文本都不能代替真实工作台验收。
5. 立即读取编辑器 DOM，核验段落、标题文字和顺序、`h1`/`h2` 数量、列表、引用、首尾哨兵句、图片数量和图片位置。该阶段只读，不得点击标题按钮或逐图上传来美化测试结果。
6. 任一结构或图片硬门槛不成立时，保留当前自动保存草稿作为诊断现场并停止，不点击 `一键排版`，也不擅自删除草稿。正常同步的 `heading_repairs` 和 `image_repairs` 都必须为 `0`；逐段、逐图修补只能在用户另行授权的兼容性诊断中使用，不能算“一次粘贴”通过。
7. 用户只要求同步草稿时，在硬门槛通过后点击一次 `一键排版`，检查排版结果，再按页面提供的草稿路径暂存；不要进入公开发布。
8. 用户明确要求公开发布时，完成排版和发布设置后，在最终发布动作前再次核验标题、正文、图片、可见范围和重复稿；最终提交最多一次。点击后只到笔记管理页核验，不因超时或未跳转而重复提交。

## 标题层级

小红书长文编辑器当前原生提供两级标题按钮，分别生成 `h1` 和 `h2`。与头条把正文小标题统一成单一大标题不同，小红书同步必须保留两级结构：

- Markdown `##` → 小红书 `h1`
- Markdown `###`、`####`、`#####`、`######` → 小红书 `h2`

小红书编辑器内部复制后再粘回，通常能保留 H1/H2；这证明平台接受带标题语义的富文本，但不能证明任意跨站 HTML 都会得到同样结果。工作台从 Markdown 直接输出 H1/H2，并优先使用浏览器原生选区复制。真实工作台整篇粘贴后必须执行只读标题 DOM 审计；若标题文字存在但 DOM 被降级为普通段落，本次一次粘贴验收失败并停止，不通过 DOM 注入或逐个点击标题按钮掩盖失败。

## 图片

- 默认保留正文图片的原始位置。是否把题图作为正文首图，以本地最终稿为准。
- 小红书内部复制的剪贴板实测把图片序列化为 `data:image/...;base64`。工作台采用同一表示，避免跨站外链图片被编辑器丢弃；不能依赖公众号 HTTPS、loopback 或 `file:` URL。
- 若一次结构化粘贴未形成等量的小红书托管图片，本次一次粘贴验收失败；保留诊断草稿并停止，不逐张复制图片来改变验收结论。
- 剪贴板中的 `data:` 只是输入表示；粘贴后图片必须转成小红书 `xhscdn` 托管地址或出现平台明确的上传完成状态。编辑器里残留的 `data:`、`file:`、`blob:`、本机环回地址和空 `src` 都不算上传成功。
- 按唯一小红书托管图片地址去重，数量必须等于预期图片数。不要因编辑器内部占位 DOM 把同一张图片重复计数。
- 正文不得残留任何兼容模式占位文字；不得把所有图片堆到文末。

## 提交前硬门槛

- 标题与用户最终标题完全一致、可见字符数不超过 64，正文没有重复文章标题、公众号篇号或微信签名。
- 正文外部链接数量为 0。
- 首段、至少两个正文哨兵句和末段存在，正文没有截断或错序。
- 小红书 `h1` 数量等于 Markdown `##` 数量；小红书 `h2` 数量等于 Markdown `###` 及更深标题数量；标题文字和顺序完全一致。
- 列表和引用至少各抽查一个存在且语义正确；不要求粘贴后的加粗保留。
- 唯一小红书托管图片数等于预期图片数，第一张和尾图都在正确位置。
- 图片占位文字残留数量为 0。
- 标题、正文或图片仍显示自动保存、上传中、处理失败时，不得点击 `一键排版`、暂存确认或最终发布。
- 笔记管理页不存在同标题的有效稿件；存在时停止，不新建第二篇。

任一条件不成立都禁止公开提交。不要把“正文大致出现”“页面没有报错”或“自动保存过”当成通过。

## 草稿与公开发布

- 三平台“同步草稿”的默认含义是：微信使用官方 API 创建草稿；头条使用 Chrome 保存草稿；小红书使用 Chrome 保存长文草稿。三者都不等于公开发布。
- 小红书自动保存只是恢复能力，不是验收结果。必须在暂存/草稿列表里确认精确标题，并记录草稿状态。
- 公开发布需要用户明确授权。最终发布动作前记录 `submission_maybe_sent=false`；点击最终按钮的瞬间改为 `true`，之后冻结所有写操作，只到笔记管理页和公开页核验。
- 若提交结果未知，只读核验精确标题和作品状态；禁止再次点击最终按钮。
- 不删除失败测试稿、旧草稿或重复稿，除非用户明确授权删除精确目标。

## 结果记录

每次小红书同步在 `<workspace>/files/<slug>.xiaohongshu-result.json` 记录：

- `title`
- `mode`: `draft`、`publish` 或 `test`
- `editor_url`
- `expected_images` 与 `verified_images`
- `expected_h1`、`verified_h1`
- `expected_h2`、`verified_h2`
- `external_links`
- `first_sentinel`、`middle_sentinels`、`last_sentinel`
- `clipboard_path`: 固定为 `macos-system`
- `clipboard_strategy`: 首选 `native-selection-rich-html`，实际降级时记录备用路径
- `platform_preview`: 应为 `xiaohongshu`
- `heading_repairs`
- `image_repairs`
- `draft_verified`
- `submission_maybe_sent`
- `management_status`
- `public_url`
- `official_api_available`: 当前应为 `false`
- `official_share_sdk_usable_for_full_sync`: 当前应为 `false`
