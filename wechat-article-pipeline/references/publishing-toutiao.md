# 今日头条 Chrome + Computer Use 发布流程

仅在用户明确要求同步、保存草稿或发布今日头条时使用本流程。复用用户 Chrome 中已有的登录态。Chrome 用于 loopback 工作台的格式选择、可见复制按钮点击与状态核验，以及头条页面检查、选项设置、提交和结果核验；Computer Use 只在外部头条编辑器页面用于 macOS 系统剪贴板粘贴。不要在 `127.0.0.1`、`localhost` 等 loopback 工作台页面调用 Computer Use；该页面可能被浏览器安全策略直接拒绝。微信草稿箱的“只用官方 API”限制只适用于 `mp.weixin.qq.com`，不限制今日头条。

## 权威内容

- 以用户确认的最终 Markdown/工作台正文为准，不从旧头条草稿反向覆盖本地稿。
- 标题使用用户指定的最终标题。正文不要重复插入文章标题、公众号原创篇号或微信专属签名。
- 来源名称可以保留为纯文本，但正文不得包含任何外网超链接；发布前必须确认正文中的外部 `href` 数量为 0。
- 复制前检查首段、关键句、末段、后记和预期图片数。

## 不可跳过的执行顺序

在第一次填写或点击头条页面前，先完整读完本文件，并从用户请求中记录：最终标题、投放方式、封面模式、是否首发、发布方式、北京时间和预期图片数。用户未指定投放方式时，记录为默认值 `投放广告赚收益`。时间表达缺少具体小时或分钟时，先完成草稿准备，但必须在最终提交前向用户确认；不要替用户猜时间。

工作台的“选择头条格式 → 点击 `复制为头条格式`”是已有工作台文章进入头条的唯一正文入口。工作台从 Markdown 语义 DOM 直接生成头条版本：移除文章总标题、公众号原创篇号和微信签名，移除所有外部链接，把正文各级小标题统一为原生 `h1`，并保留图片的原始位置。不得从已经被微信排版扁平化为段落的 HTML 二次转换。

头条复制优先使用浏览器原生选区复制，把结构化 `text/html` 与纯文本表示一起写入 macOS 系统剪贴板。带图文章必须先通过公众号官方 API 创建草稿；成功回执中的正文图片 HTTPS 托管地址会按原顺序自动回填工作台。选择或复制头条格式时，已打开的 loopback 工作台会从磁盘版本重新读取这批地址，不要求手动刷新页面。复制前检查若发现托管图缺失或数量不等，会在写入剪贴板前阻断。必须用 Chrome 在 loopback 工作台点击一次当前格式复制按钮，读取页面可见的“已复制”状态与图片数量作为成功证据；随后切换到外部头条编辑器，再用 Computer Use 在头条正文区执行一次系统粘贴。不得用浏览器虚拟剪贴板替代，不得先重建纯文字正文，不得改走头条的单图上传按钮，也不得因为通用浏览器经验而绕过本流程。

选择头条格式时即检查 Markdown 总标题的可见字符数。超过 30 字仍可复制正文，但工作台必须显示警告；在标题缩短到 30 字以内之前不得进入头条最终提交。

每次失败后都重新打开干净发布页。不要在旧稿、半成品或段落顺序不明的页面上继续修补；自动保存形成的失败草稿不得发布，也不要未经用户允许删除。

## Chrome 路径

1. 使用 Chrome 控制 skill 和 Computer Use skill，复用当前 Chrome 登录态并给会话命名。
2. 打开 `https://mp.toutiao.com/profile_v4/graphic/publish`。优先新建干净发布页，避免把旧草稿的残留正文带入。
3. 填入标题。用 Chrome 完成“工作台选择头条格式并点击复制为头条格式”，确认可见复制状态成功后切到头条；聚焦 ProseMirror，再用 Computer Use 执行一次 macOS 系统粘贴，一次性粘贴完整富文本与图片。
4. 设置封面、广告、声明等发布选项。跨平台同步默认关闭 `头条首发`；只有用户确认满足平台当前独家/时限规则时才启用。
5. 用户只要求同步草稿时，止于保存草稿。用户明确要求直接发布或定时发布时，必须先通过“提交前硬门槛”，再进入预览和最终提交。
6. 立即发布时，在作品管理页等待状态从 `审核中` 变为 `已发布`。定时发布时，验收标题对应行同时出现精确的 `将于 MM-DD HH:mm 发布` 和预期状态；不要因为审核中而重复投稿。
7. 立即发布后打开标题对应的公开链接验收。定时任务只有在用户要求继续监控时，才等待发布时间并做公开页验收。

## 定时发布状态机

头条会在不同阶段重复显示同名的 `定时发布` 按钮。按钮文字不能证明当前阶段；每次转换后都重新读取 DOM，以对话框、绝对时间和作品管理行作为唯一状态证据。禁止依赖固定等待时间、旧快照、旧元素序号或“再点一次试试”推进流程。

严格按下面五个状态执行，不得合并步骤：

1. `EDITOR_READY`：正文硬门槛全部通过。先在作品管理页检查当天是否已有同标题的 `审核中`、`定时发布中`、`已发布` 或 `仅我可见` 记录；只要存在就停止并向用户说明，不新建第二篇。
2. `TIME_DIALOG`：在编辑器底部点击一次 `定时发布`，随后等待标题为 `定时发布` 的对话框以及 `.publish-time`。预览画面、加载中的禁用按钮或另一个同名按钮都不是下一步入口。时间对话框未出现时停止，不再点击任何 `定时发布`。
3. `TIME_CONFIRMED`：设置日期、小时和分钟，读取 `.publish-time` 的完整北京时间，确认与用户要求逐字符一致，并把该字符串保存到本次结果记录。只有这时才能点击一次对话框里的 `预览并定时发布`。
4. `FINAL_PREVIEW`：等待最终预览完成，重新确认本次保存的绝对时间仍是预期值，再点击一次最终预览页的 `定时发布`。点击瞬间设置 `submission_maybe_sent=true`；本次任务的最终提交额度随即耗尽。
5. `MANAGEMENT_VERIFY`：只进行只读核验，等待进入作品管理页。精确标题对应行必须显示保存过的 `将于 MM-DD HH:mm 发布`。同日同标题只能有这一条有效记录，记录其 `pgc_id` 和状态后结束。

若最终点击后没有跳转、页面超时、连接中断或结果不明确，先到作品管理页按精确标题检查；绝对禁止再次点击最终按钮。查不到明确结果时停止并报告“提交结果未知”，不要重投。

## 单次提交熔断与一次性恢复

- 正常发布路径每篇文章每次任务最多执行一次可能产生作品记录的最终提交。点击前设置 `submission_maybe_sent=true`；重载页面、换标签页或打开干净发布页都不能把它重置为 `false`。
- 一旦 `submission_maybe_sent=true`，先冻结所有写操作，只到作品管理页和公开页做只读核验。若结果未知，先按精确标题、时间和 `pgc_id` 查明；不能把超时或未跳转当成“没有提交”。
- 如果作品管理页出现错误时间、意外立即发布、重复标题、正文截断或其他已证实的错误，记录每条相关作品的精确标题、`pgc_id`、时间、状态、展现和阅读数据。没有用户明确恢复授权时不得隐藏、删除、撤回、再次发布或另建同标题文章。
- 用户明确授权“删掉重发”后，每篇文章每次任务最多执行一次恢复事务。恢复预算字段为 `recovery_attempts_used`，初始值为 `0`；在第一次删除或其他恢复写操作之前先持久化为 `1`。重载页面、换标签页、浏览器重启或新开任务页面都不能重置该预算。
- 恢复时必须用精确标题、状态和 `pgc_id` 锁定错误行，只删除这一行，并回到作品管理页确认该 `pgc_id` 已消失。随后重新统计精确标题：如果正确的定时稿或已发布稿已经存在，清理到此结束，禁止再发；只有不存在正确作品时，才能在干净发布页重新跑完除正常提交锁以外的全部硬门槛，并最多执行一次替代稿最终提交。此时用恢复提交锁代替正常提交锁。
- 替代稿最终点击前设置 `recovery_submission_maybe_sent=true`。删除结果不明确、替代稿提交失败或未知、仍有重复行，或本次恢复开始前 `recovery_attempts_used` 已为 `1` 时，一律停止并报告；禁止第二次删除重发，也禁止用“再试一次”绕过预算。
- 结果文件必须记录 `recovery_attempts_used`、被删作品的 `pgc_id`、`deletion_verified`、替代稿 `pgc_id`（若有）以及 `replacement_submitted`。最终验收必须确保精确标题只剩一条有效记录；存在两条或以上时判定为失败并完整报告。

## 富文本与图片

先在 loopback 工作台选择“头条格式”，直观看到标题统一、微信专属元素移除和图片位置，并确认复制前检查显示可一键复制。用 Chrome 点击一次 `复制为头条格式`，并确认页面显示已复制及预期图片数；切换到外部头条页面后，再通过 Computer Use 向 ProseMirror 正文区执行一次 `super+v`。必须保留全部图片、单级标题、列表、加粗和原始顺序。正常同步不允许逐段恢复标题或逐图补传。

不要读取或拼装浏览器虚拟剪贴板，不要把页面 `execCommand('copy')` 的返回值单独当成成功。不要在 macOS 上误用 `ctrl+a` / `ctrl+v`；全选和粘贴使用 Computer Use 的 `super+a` / `super+v`。执行一次 `super+v` 后进入 `PASTE_PENDING`：带图富文本可能先显示 0 字，再异步出现正文和图片。最多等待 15 秒，期间只做只读核验，不得再次粘贴。只有等待结束后正文仍为空，才判定粘贴失败并保留现场；一旦出现正文，就用首段、末段、标题序列和按地址去重后的图片数验收。验收标准是：系统剪贴板中的完整富文本已经实际粘贴进头条编辑器，并通过下方硬门槛。

如果工作台提示托管图片缺失或数量不等，先停止并重新完成微信草稿上传/工作台回填；不要把 loopback 地址当成可交付图片。若单次系统粘贴失败，保留该干净页作为诊断现场并停止提交，报告准确错误，不自行改换正文导入方式或在目标编辑器中逐项修补。

图片进入编辑器后应被上传为头条私有图片 URL。草稿验收时按不同图片 URL 去重；编辑器内部可能为每张图保留两个 DOM `img`，不要把 DOM 数量翻倍误判为重复插图。

## 提交前硬门槛

以下条件必须全部成立，才能点击预览、立即发布或定时发布：

- 标题与用户指定标题完全一致、可见字符数不超过 30，正文没有重复标题、公众号篇号或微信签名。
- 正文中不存在带外部地址的 `<a href>`；外部链接数量必须为 0。
- 首段、至少两个正文哨兵句和末段存在；标题文字及顺序与最终稿完全一致。
- 按头条私有图片 URL 去重后的图片数等于预期图片数，第一张和尾图都在正确位置。
- 封面模式、广告、合集和作品声明符合用户请求；用户未明确要求不挂广告时，`投放广告赚收益` 必须处于选中状态；跨平台同步的 `头条首发` 保持关闭，除非用户明确确认符合规则。
- 定时发布必须显示完整的北京时间绝对值，并与用户确认的日期、小时和分钟完全一致。
- 正常提交时 `submission_maybe_sent` 必须仍为 `false`；一次性恢复提交时必须同时满足用户已授权、`recovery_attempts_used=1` 且 `recovery_submission_maybe_sent=false`。两种路径都要求当天作品管理页不存在同标题有效记录。

任一条件不成立都禁止提交。不要把“内容已经大致出现”“草稿已自动保存”或“平台没有报错”当成通过。

## 标题层级

工作台的“头条格式”预览与复制共用同一个版本化语义适配器，会主动把 Markdown `##` 到 `######` 统一转换为原生 `h1`，以匹配头条唯一的大标题样式。头条编辑器和公开页仍可能继续归一化 HTML；只要标题文字、顺序和视觉分隔正确，不要通过脆弱的 DOM 注入强行恢复层级。

## 封面和声明

- 发布头条图文时必须主动完成封面选择。除非用户另有指定，默认选择“单图”，并选用正文第一张图片作为封面；不要只依赖平台自动选择。
- 选择后检查封面缩略图确实出现，并确认缩略图与正文第一张图片一致，再进入预览或发布。
- 不要把“正文已有题图”和“单图封面”误判为重复正文图片。
- 跨平台同步默认关闭 `头条首发`。该选项涉及平台时限和独家声明，不能仅因为按钮默认勾选就保留。
- 头条图文默认选择 `投放广告赚收益`。只有用户明确要求不挂广告时，才选择 `不投放广告`；不要把“去除微信正文里的广告卡片”误解为关闭头条广告收益。
- 不依赖页面初始状态或标签序号。按可见文本定位广告选项，并读取对应单选框的实际 `checked` 状态；若目标选项未选中，主动点击后再次验证。两个广告选项都未选中时，不得保存草稿或提交。
- 每篇头条结果文件和同步日志都记录 `toutiao_ads_enabled: true|false`；默认应为 `true`。合集未指定时保持账号默认值。

## 发布后验收

作品管理页出现正确标题且状态为 `已发布` 后，打开标题链接。公开页必须满足：

- 标题与用户最终标题完全一致。
- 首段、至少两个正文哨兵句、末段和后记都存在。
- 正文包含预期图片数；检查 `data-src`/实际图片地址的唯一性。
- 头条公开页使用懒加载。逐屏向下滚动，直到每张正文图片的 `naturalWidth` 大于 1，再确认全部图片正常显示。
- 最末尾的尾图和后记可见，正文没有截断或段落错序。

若页面有问题，优先从作品管理页修改并重新验收；只有用户已授权且修改不可恢复时才删除重发。遇到 CAPTCHA 时停下并请求用户处理或授权。
