# 今日头条 Chrome + Computer Use 发布流程

仅在用户明确要求同步、保存草稿或发布今日头条时使用本流程。复用用户 Chrome 中已有的登录态。Chrome 用于页面检查、选项设置、提交和结果核验；Computer Use 专门用于工作台 `复制富文本`、macOS 系统剪贴板和头条正文粘贴。微信草稿箱的“只用官方 API”限制只适用于 `mp.weixin.qq.com`，不限制今日头条。

## 权威内容

- 以用户确认的最终 Markdown/工作台正文为准，不从旧头条草稿反向覆盖本地稿。
- 标题使用用户指定的最终标题。正文不要重复插入文章标题、公众号原创篇号或微信专属签名。
- 来源名称可以保留为纯文本，但正文不得包含任何外网超链接；发布前必须确认正文中的外部 `href` 数量为 0。
- 复制前检查首段、关键句、末段、后记和预期图片数。

## 不可跳过的执行顺序

在第一次填写或点击头条页面前，先完整读完本文件，并从用户请求中记录：最终标题、投放方式、封面模式、是否首发、发布方式、北京时间和预期图片数。用户未指定投放方式时，记录为默认值 `投放广告赚收益`。时间表达缺少具体小时或分钟时，先完成草稿准备，但必须在最终提交前向用户确认；不要替用户猜时间。

工作台的 `复制富文本` 是已有工作台文章进入头条的唯一正文入口。必须用 Computer Use 点击该按钮，让富文本进入 macOS 系统剪贴板，再用 Computer Use 在头条正文区执行一次系统粘贴。不得用浏览器虚拟剪贴板替代，不得先重建纯文字正文，不得改走头条的单图上传按钮，也不得因为通用浏览器经验而绕过本流程。

每次失败后都重新打开干净发布页。不要在旧稿、半成品或段落顺序不明的页面上继续修补；自动保存形成的失败草稿不得发布，也不要未经用户允许删除。

## Chrome 路径

1. 使用 Chrome 控制 skill 和 Computer Use skill，复用当前 Chrome 登录态并给会话命名。
2. 打开 `https://mp.toutiao.com/profile_v4/graphic/publish`。优先新建干净发布页，避免把旧草稿的残留正文带入。
3. 填入标题。用 Computer Use 完成“工作台点击复制富文本 → 切到头条 → 聚焦 ProseMirror → macOS 系统粘贴”，一次性粘贴完整富文本与图片。
4. 设置封面、广告、声明等发布选项。跨平台同步默认关闭 `头条首发`；只有用户确认满足平台当前独家/时限规则时才启用。
5. 用户只要求同步草稿时，止于保存草稿。用户明确要求直接发布或定时发布时，必须先通过“提交前硬门槛”，再进入预览和最终提交。
6. 立即发布时，在作品管理页等待状态从 `审核中` 变为 `已发布`。定时发布时，验收标题对应行同时出现精确的 `将于 MM-DD HH:mm 发布` 和预期状态；不要因为审核中而重复投稿。
7. 立即发布后打开标题对应的公开链接验收。定时任务只有在用户要求继续监控时，才等待发布时间并做公开页验收。

## 富文本与图片

先用 Computer Use 在 loopback 工作台点击 `复制富文本`，等待工作台明确显示复制成功，再用 Computer Use 通过 macOS 系统剪贴板把完整正文一次粘贴到头条 ProseMirror 正文区。必须保留全部图片、标题层级、列表、加粗和原始顺序。

不要读取或拼装浏览器虚拟剪贴板，不要把页面 `execCommand('copy')` 的返回值单独当成成功。不要在 macOS 上误用 `ctrl+a` / `ctrl+v`；全选和粘贴使用 Computer Use 的 `super+a` / `super+v`。验收标准是：系统剪贴板中的完整富文本已经实际粘贴进头条编辑器，并通过下方硬门槛。

如果系统剪贴板粘贴失败，重新执行“工作台复制富文本 → 系统剪贴板一次粘贴”；仍失败则停止提交并报告准确错误，不自行改换正文导入方式。

图片进入编辑器后应被上传为头条私有图片 URL。草稿验收时按不同图片 URL 去重；编辑器内部可能为每张图保留两个 DOM `img`，不要把 DOM 数量翻倍误判为重复插图。

## 提交前硬门槛

以下条件必须全部成立，才能点击预览、立即发布或定时发布：

- 标题与用户指定标题完全一致，正文没有重复标题、公众号篇号或微信签名。
- 正文中不存在带外部地址的 `<a href>`；外部链接数量必须为 0。
- 首段、至少两个正文哨兵句和末段存在；标题文字及顺序与最终稿完全一致。
- 按头条私有图片 URL 去重后的图片数等于预期图片数，第一张和尾图都在正确位置。
- 封面模式、广告、合集和作品声明符合用户请求；用户未明确要求不挂广告时，`投放广告赚收益` 必须处于选中状态；跨平台同步的 `头条首发` 保持关闭，除非用户明确确认符合规则。
- 定时发布必须显示完整的北京时间绝对值，并与用户确认的日期、小时和分钟完全一致。

任一条件不成立都禁止提交。不要把“内容已经大致出现”“草稿已自动保存”或“平台没有报错”当成通过。

## 标题层级

工作台可提供真实的 `h2`/`h3`，但头条当前编辑器会把粘贴的多级标题统一转换成平台唯一的大标题样式，公开页 DOM 常全部显示为 `h1`。这是平台归一化。只要标题文字、顺序和视觉分隔正确，不要通过脆弱的 DOM 注入强行恢复层级。

## 封面和声明

- 发布头条图文时必须主动完成封面选择。除非用户另有指定，默认选择“单图”，并选用正文第一张图片作为封面；不要只依赖平台自动选择。
- 选择后检查封面缩略图确实出现，并确认缩略图与正文第一张图片一致，再进入预览或发布。
- 不要把“正文已有题图”和“单图封面”误判为重复正文图片。
- 跨平台同步默认关闭 `头条首发`。该选项涉及平台时限和独家声明，不能仅因为按钮默认勾选就保留。
- 头条图文默认选择 `投放广告赚收益`。只有用户明确要求不挂广告时，才选择 `不投放广告`；不要把“去除微信正文里的广告卡片”误解为关闭头条广告收益。
- 不依赖页面初始状态或标签序号。按可见文本定位广告选项，并读取对应单选框的实际 `checked` 状态；若目标选项未选中，主动点击后再次验证。两个广告选项都未选中时，不得保存草稿或提交。
- 每篇头条结果文件和同步日志都记录 `toutiao_ads_enabled: true|false`；默认应为 `true`。合集未指定时保持账号默认值。

## 发布后验收

作品管理页出现正确标题且状态为 `已发布` 后，打开标题链接。公开页必须满足：

- 标题与用户最终标题完全一致。
- 首段、至少两个正文哨兵句、末段和后记都存在。
- 正文包含预期图片数；检查 `data-src`/实际图片地址的唯一性。
- 头条公开页使用懒加载。逐屏向下滚动，直到每张正文图片的 `naturalWidth` 大于 1，再确认全部图片正常显示。
- 最末尾的尾图和后记可见，正文没有截断或段落错序。

若页面有问题，优先从作品管理页修改并重新验收；只有用户已授权且修改不可恢复时才删除重发。遇到 CAPTCHA 时停下并请求用户处理或授权。
