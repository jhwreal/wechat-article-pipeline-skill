# 今日头条 Chrome 发布流程

仅在用户明确要求同步、保存草稿或发布今日头条时使用本流程。复用用户 Chrome 中已有的登录态；不要使用 Computer Use。微信草稿箱的“只用官方 API”限制只适用于 `mp.weixin.qq.com`，不限制今日头条。

## 权威内容

- 以用户确认的最终 Markdown/工作台正文为准，不从旧头条草稿反向覆盖本地稿。
- 标题使用用户指定的最终标题。正文不要重复插入文章标题、公众号原创篇号或微信专属签名。
- 复制前检查首段、关键句、末段、后记和预期图片数。

## Chrome 路径

1. 使用 Chrome 控制 skill，复用当前 Chrome 登录态并给会话命名。
2. 打开 `https://mp.toutiao.com/profile_v4/graphic/publish`。优先新建干净发布页，避免把旧草稿的残留正文带入。
3. 填入标题。将工作台正文作为富文本粘贴到 ProseMirror 正文区。
4. 设置封面、广告、声明等发布选项。跨平台同步默认关闭 `头条首发`；只有用户确认满足平台当前独家/时限规则时才启用。
5. 用户只要求同步草稿时，止于保存草稿。用户明确要求直接发布时，进入预览，核对标题和封面，然后确认发布。
6. 在作品管理页等待状态从 `审核中` 变为 `已发布`。不要因为审核中而重复投稿。
7. 打开标题对应的公开链接，检查标题、首段、关键句、末段、后记、标题样式和所有图片。

## 富文本与图片

先尝试从 loopback 工作台直接复制富文本。Chrome 控制环境的系统剪贴板与浏览器虚拟剪贴板可能隔离；页面 `execCommand('copy')` 成功不代表自动化按键能读取该内容。遇到 `virtual clipboard has no data` 时，使用 `tab.clipboard.write` 写入 `text/html` 和 `text/plain`，不要切换到 Computer Use。

不要把包含多张原始 PNG 的超大 HTML 一次性写入虚拟剪贴板。一次约 1 MB 的富文本可能断开 Chrome 扩展连接。稳妥路径：

1. 在临时目录为头条生成网页发布级 JPEG 副本；保留项目内原始 PNG，不覆盖源图。
2. 将文章按图片切成小段，每段最多一张内嵌图片；建议单段 HTML 控制在约 300 KB 内。
3. 第一段从正文占位符粘贴。
4. 后续每段先定位唯一的 `[contenteditable="true"]` 正文区，再按 `ControlOrMeta+ArrowDown` 到文末、按 `Enter` 新建块、粘贴下一段。
5. 每段粘贴后立即用下一段前的唯一标题或末句验收。头条上传图片时可能抢走光标；没有验收信号就不要继续下一段。

图片进入编辑器后应被上传为头条私有图片 URL。草稿验收时按不同图片 URL 去重；编辑器内部可能为每张图保留两个 DOM `img`，不要把 DOM 数量翻倍误判为重复插图。

## 标题层级

工作台可提供真实的 `h2`/`h3`，但头条当前编辑器会把粘贴的多级标题统一转换成平台唯一的大标题样式，公开页 DOM 常全部显示为 `h1`。这是平台归一化。只要标题文字、顺序和视觉分隔正确，不要通过脆弱的 DOM 注入强行恢复层级。

## 封面和声明

- 单图封面通常可自动使用正文第一张图；选择后检查封面缩略图确实出现。
- 不要把“正文已有题图”和“单图封面”误判为重复正文图片。
- 跨平台同步默认关闭 `头条首发`。该选项涉及平台时限和独家声明，不能仅因为按钮默认勾选就保留。
- 保持用户未特别指定的广告与合集设置为账号默认值。

## 发布后验收

作品管理页出现正确标题且状态为 `已发布` 后，打开标题链接。公开页必须满足：

- 标题与用户最终标题完全一致。
- 首段、至少两个正文哨兵句、末段和后记都存在。
- 正文包含预期图片数；检查 `data-src`/实际图片地址的唯一性。
- 头条公开页使用懒加载。逐屏向下滚动，直到每张正文图片的 `naturalWidth` 大于 1，再确认全部图片正常显示。
- 最末尾的尾图和后记可见，正文没有截断或段落错序。

若页面有问题，优先从作品管理页修改并重新验收；只有用户已授权且修改不可恢复时才删除重发。遇到 CAPTCHA 时停下并请求用户处理或授权。
