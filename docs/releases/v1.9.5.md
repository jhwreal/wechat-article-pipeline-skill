# v1.9.5：主动选取金句与交付前重点检查

发布日期：2026-10-21。基于 v1.9.4 的补丁发布，改进文章重点表达和引用框使用规则。

## 问题与修改

近期文章初稿缺少重点引用，旧自动标注又依赖固定提示词和评分门槛，容易漏掉自然表达的核心判断；过去也出现过引用框过密、满篇都是重点的问题。

- 写稿时按内容主动选择值得读者记住或转述的核心句，以 Markdown `>` 标记，沿用浅灰底、左侧色条的微信引用框。
- 保持稀疏：普通 1000–2000 字文章以 1–3 处为参考，不作为配额，不要求每节都有，不重复正文、不凭空拔高观点。
- 交付前与完整检查时复核金句质量、位置和视觉密度，区分漏标、过密与缺少有力核心判断。
- 没有合适金句时明确提出问题，给出具体结构调整、候选句和放置位置。仅检查时不修改原文，此项优化本身不阻断已授权交付。
- 常规技能命令显式传入 `--no-focus-marking`，保留写作时的选择。旧关键词评分仅作可选候选辅助；底层 CLI 省略该参数时仍维持原有行为。
- 压缩技能入口中的重复流程说明，保持仓库的入口长度约束，完整规则集中在 `references/style-guide.md`。
