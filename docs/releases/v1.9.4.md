# v1.9.4：保护稿件版本与公众号账号隔离

发布日期：2026-10-13。基于 v1.9.3 的补丁发布，处理本次审计中优先级最高的三类问题。

## 问题与修改

1. 工作台已经打开后，如果编辑器或 Agent 单独修改源 Markdown，旧页面保存过去可能覆盖新稿。现在保存前核对持久化源文件基线，遇到外部变化拒绝覆盖并保留稿件。
2. 已生成发布清单后，只修改 Markdown，过去仍可能上传旧清单内容，并用新稿指纹写回结果。现在发布前验证来源版本，交付回执绑定实际提交的文章快照。
3. 明确选择命名账号 B，但 B 缺少凭据时，过去可能回退到旧配置中的账号 A。现在命名账号不继承全局 legacy credentials，缺少必要配置时停止；默认账号的旧配置和显式一次性参数保持兼容。

同时纳入此前已同步到本机的两项维护：四列以内的工作台表格换行适配容器；头条正常新建定时发布直接进入时间设置，提交结果不明确时仍只读核验并遵守单次提交限制。

## 验证

- 新增 38 项回归：工作台源文件冲突与恢复 12 项、发布来源快照 12 项、命名账号凭据与恢复 11 项、前端冲突提示与禁用编辑 3 项。
- 全量 289 项通过：仓库 Python 204 项、技能 Python 30 项、JavaScript 55 项。使用 Python 3.12.14 和 Node 25.9.0。
- Python 编译、版本元数据和 `git diff --check` 通过。测试覆盖默认重点标记和图片占位符、无图转换、CRLF、浏览器保存后完整重包、上传中改稿和恢复回执身份。
- 保存冲突经过真实本机 HTTP 请求验证；微信上传使用模拟接口，打包和 API dry-run 在临时文章中执行，未向真实平台创建草稿。
- 安装同步按 README 的发布文件范围执行，并使用 `doctor --require-installed-sync` 检查；本机配置、篇号和缓存保留。

## 升级与回退

按 README 同步技能发布文件，保留本机 `.env`、篇号、账号凭据和缓存。已有文章内容不随升级修改；检测到源文件与包不一致时，应从用户确认的最新稿重新打包，不强行保存旧页面。

新包记录原始 Markdown 快照，兼容其与重点标记稿、图片路径之间的表示差异。无法证明来源一致的旧发布清单需要重包；独立旧清单仍可使用，但不证明当前本地 Markdown 已交付。没有历史保存基线、也没有源快照的旧工作台，首次启动只能建立当前基线，不能追溯此前的外部修改。打开中的旧工作台如需新冲突提示，应重新打包并重启服务。

回退使用新提交 revert 本补丁，或从 v1.9.3 恢复技能发布文件后同步；不移动已发布标签，不覆盖本机配置。

本补丁仅处理三项优先问题，其余审计项继续作为后续维护记录。
